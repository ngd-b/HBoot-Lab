# Spoken short-video publishing rules

## Source of truth

Read `content/video/口播短视频滚动发布计划.md` completely before creating or substantially revising an episode. Read the previous episode, the target episode if it exists, the next planned episode, and the relevant product or article evidence.

## Content standard

- Public language is conversational Chinese intended to be spoken aloud.
- Each episode teaches one concrete thing. Split multiple directions into separate episodes.
- The first two seconds must state a conflict, mistake, surprising result, or direct viewer problem. Do not start with a greeting or series introduction.
- Use a real action sequence: what happened, what was done, what problem appeared, and what to watch for.
- AI participation must be concrete when it is part of the experience: what AI read, produced, changed, or failed to handle, and where human judgment was needed.
- Avoid repeated `我怎么样` sentence openings, abstract conclusions, technical dumping, and filler that teaches nothing.
- Maintain continuity with the published episode immediately before it, but make the episode understandable on its own.
- Target the duration and format in the live plan, normally 45–75 seconds in 9:16 with full subtitles.

## Protect the user's script

The user's spoken draft is the master copy. If the user says they rewrote it, preserve it exactly. A request such as `梳理内容，更新标题、文案、标签` does not authorize rewriting the spoken body. Only change the spoken body when explicitly requested.

## Repository record

Store each episode under `content/video/scripts/` using its series number and a descriptive Chinese filename. Keep the file and `content/video/口播短视频滚动发布计划.md` synchronized.

An episode file should contain the existing repository structure as applicable: series title, status, viewer takeaway, spoken master, per-platform titles, descriptions, tags, and visual/evidence notes.

When generating metadata:

- 视频号 title states the full useful point.
- 抖音 title and opening emphasize the conflict immediately.
- 小红书 title or cover includes the series number and a searchable problem term.
- Descriptions summarize the concrete value without repeating the entire script.
- Tags stay relevant and limited; do not add broad trending tags with no connection.

When the user says the episode is published, set the script and plan status to `已发布`, record the current Asia/Shanghai date and time in the plan, and preserve the spoken copy.

## Preflight

- Spoken body is unchanged when it is user-authored and locked.
- First two seconds contain the hook.
- Only one useful topic is taught.
- Sentences sound natural when read aloud.
- Previous and next episodes connect without repeating each other.
- Titles, descriptions, tags, file name, number, and plan entry agree.
