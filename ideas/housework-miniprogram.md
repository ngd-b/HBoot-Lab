## 产品目标

帮一个家庭记住家务、判断先做什么，并看见彼此做过什么。减少从零建立清单、记住清洁时间和协调家务的负担。

核心流程：

```text
选房间和任务 → 设清洁周期 → 查看优先清单 → 完成并记录 → 家人同步、看到贡献
```

加入 AI 后，建立计划可以增加一个入口：

```text
描述自己的家／选模板 → 确认任务和周期 → 查看优先清单 → 完成记录 → 家人同步
```

## 竞品设计依据

讨论参考 Tody、Sweepy 的官方功能和用户评论。以下六项有成熟产品采用，可作为设计依据；国内用户是否需要、愿意持续使用，仍需实际验证。

| 方向 | 讨论依据及可借鉴之处 |
| --- | --- |
| 按房间快速建立家务 | 预置房间和任务，勾选后修改周期，也能自定义。Sweepy 评论中有用户认可无需从零录入，同时希望删除不适用的任务。[功能与评论](https://apps.apple.com/au/app/sweepy-home-cleaning-schedule/id1498897320) |
| 记住上次完成时间 | Tody 以距上次完成的时间与周期判断到期程度，完成后重新计算，也支持固定星期。此状态是时间推算。[官方说明](https://todyapp.com/faq) |
| 告诉用户先做什么 | Tody 提供优先清单、房间状态和完成记录；讨论整理的用户反馈包括减少记忆负担、拆分大扫除和看见已完成的工作。[官方功能](https://todyapp.com/method) · [用户评论](https://apps.apple.com/gb/app/tody/id595339588?platform=iphone&see-all=reviews) |

| 家人共享和贡献记录 | 两家均有家庭协作，包含同步完成状态和记录执行人。讨论整理的 Tody 评论中有多人共同使用的正面反馈。[用户评论](https://play.google.com/store/apps/details?id=com.looploop.tody) |
| 积分和轻量游戏化 | Tody 的角色挑战、Sweepy 的家庭榜单有用户认可其激励作用。可以考虑积分、挑战或榜单，再评估复杂装饰系统。[Tody 评论](https://play.google.com/store/apps/details?id=com.looploop.tody) · [Sweepy 评论](https://apps.apple.com/us/app/sweepy-home-cleaning-schedule/id1498897320?see-all=reviews) |

按精力自动排班和复杂游戏化分阶段安排，是控制开发量的建议，不能据此判断它们没有价值。

## 建议首版功能

| 功能 | 范围 |
| --- | --- |
| 房间和任务模板 | 提供厨房、卫生间、卧室等模板；可勾选、改名、删除任务，也能自定义房间和任务。 |
| 清洁周期 | 先支持每隔 N 天；模板给出可修改的建议周期。 |
| 优先清单 | 根据完成时间和周期排列，支持按房间筛选。 |
| 完成记录 | 一键完成，记录实际完成时间和执行人，支持撤销误操作。 |
| 家庭共享 | 邀请成员加入同一家庭，共享任务和完成状态。 |
| 贡献查看 | 显示各成员的本周完成次数及具体完成任务。 |
| AI 建立计划 | 根据家庭描述生成房间、任务和建议周期，用户编辑、确认后加入。 |
| AI 修改计划 | 理解自然语言调整要求，展示修改内容，用户确认后生效。 |

模板录入和手工修改始终可用；AI 请求失败时，用户仍能建立计划并继续记录家务。

## 建议业务规则

### 周期和到期程度

- 到期程度 = 距上次有效完成的时间 ÷ 设定周期。例如周期为 7 天，距上次完成已过 10 天，则到期程度约为 143%。
- 界面使用“还有几天到期”“已到期”等时间措辞，不能把推算结果表述为实际检测到家里脏了。
- 首次建立任务时，可填写上次完成日期。记不清则标记为“待首次完成”，单独提示，不虚构完成时间。
- 已到期任务按到期程度从高到低排序；待首次完成任务单独展示。未到期任务的展示顺序、同分排序和状态阈值待定。
- 优先清单给出处理顺序，不要求当天全部做完；首版由用户选今天愿意做的任务。
- 提前完成也从实际完成时间重新计算周期。
- “今天先不做”只影响当天展示，不记作完成，也不重置到期状态；具体入口与恢复方式待设计。
- 首版建议按天设置周期。固定星期、一天内多次任务的支持方式后续确定。

### 完成记录和家庭同步

- 家庭成员使用同一份任务状态，完成记录包含任务、时间和执行人。
- 两人同时完成同一次待办时，只保留一次有效完成，避免重复计入贡献。
- 撤销完成后，恢复上一条有效完成记录对应的周期状态和贡献统计。可撤销范围与权限待定。
- 删除任务后停止参与后续清单，已有完成记录保留。
- 首版贡献展示事实：完成次数和具体任务。完成次数不能直接等同于劳动量或公平程度。
- 家庭共享包含状态同步、执行人和贡献，不能只分享一份静态清单。

## AI 功能设想

### 优先加入首版 一句话建立计划

用户输入：

> 我家两室一厅，两个人住，有猫。平时比较忙，周末能多做一点。

AI 输出可修改的草案：

- 房间建议：厨房、卫生间、客厅、两个卧室。
- 任务建议：清理台面、清洁马桶、吸尘、换洗床品、清理猫砂盆等。
- 每项任务的初始周期，以及与养宠、使用频率等条件有关的简短说明。
- 必要时少量追问，例如“猫砂盆需要加入每日任务吗？”

用户可以删除不适用的任务、修改周期，再确认加入。建议周期是起点，后续按实际习惯调整。“工作日忙、周末多做”先记录为偏好，不能在尚无排班功能时承诺已生成周排程。

### 优先加入首版 自然语言修改计划

用户输入：

> 厨房容易有油，想清得勤一点；窗户暂时不用管。

AI 展示具体调整草案：哪些任务缩短周期、哪些任务暂停。用户确认后生效；周期修改和暂停的实际含义由业务规则处理。

新增任务和修改任务都先展示结果，避免只返回一段聊天文字。模型不能虚构完成时间、执行人或完成记录。

### 后续 根据当天情况挑任务

- 支持“今天很累，只想做一点”“有半小时，先做厨房”等描述。
- 从家庭已有任务中，结合到期程度、房间偏好和当天精力推荐少量任务，并说明原因。
- 周期和到期程度继续按明确规则计算，AI 负责理解条件和辅助选择。
- 涉及时长时需有估计依据；可以让用户补充实际耗时，逐步改善推荐。没有依据时不能承诺任务一定能在指定时间内完成。
- 此功能与工作量点数、每日投入额度和自动排班一起评估，不固定为每天三件。

### 后续 拆分模糊家务

用户说“周末想把卫生间收拾一下”，AI 建议拆成洗台盆、刷马桶、擦镜子、清地漏等可勾选任务。用户确认后再加入清单，注意与已有任务去重。

### 后续 拍照补充任务

拍摄厨房等区域后，识别可见物品，建议补充抽油烟机、灶台、微波炉等清洁任务。识别结果由用户确认；照片不能代表完整房间，也不能据此可靠判断卫生状态或必须清洁的时间。

文字建立计划优先于拍照入口。语音输入可作为后续输入方式，其接入和识别能力需另行核对。

## 现有 AI 能力复用方向

优先评估接入 [HBoot 能力服务平台](../infrastructure/unified-ai.md)，用于家庭描述理解、结构化任务草案和计划修改。

平台现有记录包含对话、结构化输出和图像元素识别，但具体能力受部署地域、授权、配置和额度限制。新小程序的目标环境、模型可用性、调用耗时及成本需在开发时核对，不能直接假定已有记录中的能力均可用于国内首版。

家务任务、周期、完成记录和贡献由产品保存并按业务规则处理。模型返回的任务和修改草案应校验、预览，确认后再写入。

## 验收场景

### 核心家务流程

1. 用户选择厨房模板，保留三项任务并修改周期。
2. 邀请家人加入，双方看到同一份任务。
3. 家人完成其中一项，双方看到任务重新计时、完成记录和贡献更新。
4. 两人同时点击同一次待办，只计一次有效完成。
5. 撤销误操作后，周期、完成记录和贡献统计一致恢复。

### AI 流程

1. 用户描述家庭情况，AI 给出可编辑的房间、任务和周期草案。
2. 用户删除不适用任务、修改周期并确认，只有最终确认内容进入计划。
3. 用户用自然语言调整现有计划，先看到明确的修改，再确认应用。
4. 模型返回无效结果或请求失败时，原计划保持可用，用户可手工操作。
