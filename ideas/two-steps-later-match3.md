# 两步之后

## 状态

**⏸ 已记录，计划后续验证（2026-08-29）**

当前只保留玩法、视觉和技术方案，不进入代码开发，也不加入当前项目列表。

工作名称：**两步之后**

玩法类型：带动作回声机制的三消小游戏

这个项目与[人物关系剧情消除小游戏](relationship-elimination-game.md)相互独立。人物关系消除依靠剧情线索和关系判断；《两步之后》的特点来自棋盘规则本身。

## 一句话玩法

> 玩家现在进行的方块交换，会在两步之后，于原来的两个格子上自动再执行一次。

玩家不只解决当前棋盘，还需要利用接下来的两步，把合适的方块送到即将发生回声的位置。

## 核心规则

- 棋盘暂定为 7×7
- 使用 5 种不同颜色和形状的基础方块
- 玩家交换相邻方块，三个及以上相同方块连成横线或竖线后消除
- 每次产生即时消除的玩家交换都会被记录
- 玩家再完成两次操作后，这次交换在原来的两个格子上自动重演
- 回声交换的是触发时位于两个格子上的新方块，不追踪原来的方块对象
- 回声即使没有形成消除，也会完成交换，不自动交换回来
- 回声本身不产生新回声，避免无限循环
- 多个回声同时到期时，按照创建顺序依次执行
- 一个回声引起的消除、下落和补充全部结束后，才执行下一个回声

棋盘需要显示固定在格子上的半透明交换箭头和倒计时：

```text
↔ 2：玩家还可以操作两步
↔ 1：玩家还可以操作一步
↔ 0：本回合结束后自动执行
```

## 回合顺序

每个回合严格按照固定状态机执行：

```text
等待玩家操作
→ 玩家交换
→ 普通消除
→ 方块下落和补充
→ 棋盘完全稳定
→ 回声倒计时推进
→ 执行到期回声
→ 回声消除
→ 再次下落和补充
→ 判断关卡胜负
→ 等待下一步操作
```

动画期间禁止玩家继续操作。棋盘数据是唯一真实状态，动画只负责表现，不能直接决定游戏结果。

## 一局示例

第一步，玩家交换第 4 行的两个方块，消除三个蓝色方块。交换位置留下“↔ 2”。

第二步，玩家在其他位置完成消除，同时让黄色方块向回声位置靠近，倒计时变为“↔ 1”。

第三步，玩家再次调整棋盘。普通消除和下落完成后，第一次交换自动重演，触发时位于那两个格子上的黄色方块被交换，并产生四连消。

玩家利用的不是过去的方块，而是过去留下的交换位置和方向。

## 关卡目标

前期目标：

- 消除指定数量的某类方块
- 在规定步数内达到目标分数
- 完成指定次数的回声消除

中期可以加入：

- **时间锁**：普通消除无效，只能被回声消除破坏
- **静止格**：位于其中的方块不会被回声交换
- **快进**：让指定回声提前执行
- **剪片**：删除一次不希望发生的回声

第一版只加入时间锁，不同时实现所有特殊元素。

## 得分反馈

- 普通消除获得基础分
- 回声消除获得更明显的视觉和声音反馈
- 回声四连、五连和连续回声形成额外奖励
- 部分关卡只统计由回声完成的目标，促使玩家主动规划回声

是否设置双倍分、连锁倍率和特殊方块，等原型验证后再确定，避免数值系统掩盖核心玩法问题。

## 新手引导

前 3 关使用固定棋盘，不使用随机掉落：

1. 第一关直接演示交换会在两步后重演。
2. 第二关要求玩家提前把目标方块放到回声位置。
3. 第三关加入只能由回声消除的时间锁。

第 4 关以后再使用随机棋盘。教学目标不是解释“时间循环”概念，而是让玩家看懂胶片倒计时，并主动利用一次回声完成目标。

## 视觉设计

整体采用**复古时光放映室**风格，不使用常见的糖果、水果和卡通动物三消包装。

核心视觉概念：

> 玩家每走一步，就像录下一格胶片；两步之后，这格胶片会被重新播放。

视觉方向：

- 温暖米白色背景，带轻微旧相纸或放映室质感
- 深蓝作为主色，珊瑚红、湖蓝和金黄作为强调色
- 扁平插画与少量颗粒，不投入复杂 3D 资产
- 方块使用圆角几何图形，避免糖果式高光
- 时间相关元素使用胶片、放映灯、残影和刻度表达

五种基础方块暂定为：

- 太阳
- 月亮
- 水滴
- 叶子
- 星星

每种方块同时使用不同形状和颜色，不能只依赖颜色区分。

## 界面布局

```text
┌────────────────────┐
│ 关卡 08    剩余 12 步 │
│ 目标：回声消除 × 4    │
├────────────────────┤
│                    │
│      7 × 7 棋盘     │
│                    │
├────────────────────┤
│  胶片时间轴          │
│ [即将播放] [还有1步]  │
└────────────────────┘
```

底部胶片时间轴代替普通技能栏，展示即将执行的交换记录。长按胶片时，高亮棋盘上对应的两个格子。

## 回声动画

玩家完成有效交换后：

- 两个格子之间留下半透明箭头
- 箭头旁显示倒计时
- 回声触发时背景短暂压暗
- 放映光束扫过胶片和目标格子
- 两个格子出现旧胶片残影并自动交换
- 使用独立的“咔嗒”声音区分普通交换和回声交换

单次回声表现控制在约半秒，不让频繁动画破坏三消节奏。

```text

```

第一版不需要业务后台。排行榜、云存档、远程活动和跨设备进度在验证玩法后再决定是否接入。

回声记录的最小数据：

```ts
interface EchoAction {
  id: string
  triggerTurn: number
  from: { row: number; col: number }
  to: { row: number; col: number }
}
```

需要使用固定随机种子生成棋盘，并记录每一步玩家交换和回声执行结果，保证问题可以稳定重现和完整回放。

## 技术成熟度

- 标准三消扫描、消除、下落、补充和死局洗牌均为成熟实现
- 回声机制本质上是一个按照回合触发的强制交换队列，不需要新的底层算法
- 7×7 棋盘的数据规模很小，普通手机不存在明显计算压力
- Cocos Creator 已提供微信小游戏构建和平台适配能力

技术风险较低。主要风险来自：

- 玩家是否能看懂回声将在哪两个格子发生
- 多个回声连续执行时，结果是否仍然可以预测
- 回声动画是否频繁打断操作节奏
- 随机掉落是否让玩家的提前规划失去意义
- 关卡是否真的要求使用回声，而不是忽略回声也能通过

## 测试重点

- 原方块已经移动后，回声仍交换正确的固定坐标
- 两个回声使用重叠格子时执行顺序稳定
- 回声没有形成消除时不自动撤销
- 回声引起多次连锁后，后续回声仍使用最新棋盘
- 最后一步结束时，先执行应到期的回声，再判断失败
- 回声不能生成新的回声
- 初始棋盘没有自动三连，并且至少存在一个有效交换
- 棋盘死局后可以安全洗牌，不破坏已有回声提示

## MVP 范围

- 7×7 棋盘和 5 种基础方块
- 标准交换、消除、下落和连锁
- 两步延迟的固定坐标回声
- 胶片时间轴和棋盘回声箭头
- 3 个固定教学关卡
- 12～17 个普通验证关卡
- 1 种时间锁障碍
- 本地关卡进度
- 基础音效和回声动画

首版不做剧情、装修、体力、商城、排行榜、社交竞争和复杂特殊方块。

## 相似玩法检索结论

截至 2026-08-29，已检索中英文网页、Google Play、App Store、Steam、itch.io 和相关专利关键词，暂未发现“玩家交换方块，两步后在原位置自动重复交换”完全相同的三消游戏。

已经存在“过去动作由回声重演”的其他类型游戏：

- [Time Echo](https://play.google.com/store/apps/details?id=com.timeecho.game)
- [Loopling](https://apps.apple.com/qa/app/loopling-time-loop-puzzles/id6779392635)
- [UnLoop](https://www.meta.com/blog/unloop-launch/)

因此，“动作回声”不是全新的基础概念，但把它放进三消棋盘，并让固定坐标上的交换影响已经变化的未来棋盘，目前看属于相对新的玩法组合。该检索不等于完整的市场或专利排查，也不能证明世界上绝对没有相同实现。

## 启动前验证

先使用纯色方块制作低成本原型，不投入正式美术。

原型需要验证：

- 玩家完成 3 个教学关卡后，能否说清回声规则
- 玩家是否会主动把方块送到即将发生回声的位置
- 回声触发时，玩家能否理解结果来自自己两步前的操作
- 玩家是否觉得是在计划未来，而不是棋盘随机自动变化
- 连续玩 10 关后，玩法是否仍然有新的决策空间

只有在玩家能够理解并主动利用回声后，才制作正式胶片视觉、更多障碍和完整关卡。
