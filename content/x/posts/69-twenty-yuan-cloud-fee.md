# 69｜A ¥20 cloud fee and a backend

- 日期：2026-09-29
- 状态：已发布
- 字符数：263

## English

> I built a backend to avoid a ¥20/month cloud bill.
>
> I already had a server, so handling uploads, storage and processing jobs myself looked cheaper. I saved the fee and took on the maintenance.
>
> Would you pay ¥20/month to skip building that part of your first app?

## 中文校对

> 为了省每月 20 元的云服务费，我自己搭了后端。
>
> 我本来就有服务器，自己处理上传、存储和任务看起来更省钱。那笔月费省了，后端的维护也落到了自己身上。
>
> 如果是你，会花每月 20 元省掉第一款产品的这部分开发吗？

## 配图

纯文字。无需制作虚构的费用账单或架构图；金额是作者历史开发记录中的当时价格，不作为当前平台报价。

## 选题门槛

- 读者：预算有限、已有服务器、在托管服务与自建后端之间取舍的独立开发者。
- 可带走的判断：比较方案时不能只看月费，还要计入自己接手的搭建和后续维护；已有服务器也会影响增量成本。
- 真实取舍：当时计划使用的云服务要每月 20 元，作者改为在已有服务器上搭业务后端并连通上传、存储及处理任务，省掉该项云服务费用；自建带来维护责任，未量化时间成本。
- 可回应的问题：读者自己在何种托管价格下会改选购买服务，答案取决于预算、已有基础设施和维护时间。

## 发布依据

- `products/ai-cut/launch/first-week-review.md` 明确记录：最初考虑云服务，因每月 20 元费用决定自己搭 Node + Koa 业务后端；此前已有入门服务器和域名。该后端连接小程序与抠图服务，上传图片、保存到存储并下发处理任务。
- 本文将 ¥20 作为历史当时的报价和取舍动因，不声称现价仍是该数，不声称自建总成本低于托管服务，也不编造实际维护小时数。
- 与 #65 的模型部署性能不同，本帖只谈现金月费与自建维护之间的选择。
- 未声称托管方案更好或更差，末尾问题围绕作者当时面对的具体月费与开发工作，可以让读者从自身经历回答。
