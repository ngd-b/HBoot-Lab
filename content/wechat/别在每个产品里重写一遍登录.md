# HBoot-Lab #020｜别在每个产品里重写一遍登录

我做了好几个小程序，每个都要登录。最早每个产品自己写一套：微信扫码、登录态、虚拟支付，还有自己的管理后台和管理员账号。写到第三个产品的时候我发现，这套东西我写了三遍，一遍比一遍烦。

于是我停下来想：这些里面，到底哪些是我的产品该管的，哪些是重复劳动。答案是，抠图的核心是抠图，记账的核心是记账，没有一个是「证明你是谁」，也不是「收钱发货」，更不是「谁是管理员」。登录、支付、后台权限这些通用的活，只应该有一个地方做。

所以我把它抽出来，做了一个统一平台。小程序这边，登录、虚拟支付这些微信相关的接口，产品不用再自己实现一遍；Web 端也是，直接跳统一登录，产品后端不用自己判断登录态、不用自己写登录页。连管理员也一样，一个后台统一管产品、区分权限，不用每个产品各做一套管理员体系。

这里要说清楚：统一的是「登录」和这些公共能力，不是数据。抠图的图、记账的账，本来就不该互通，统一之后还是各存各的；产品该自己做的业务逻辑，一点没少。

产品接入之后就轻了。一个 API Key、几行 SDK，登录、刷新、退出、支付、微信扫码全交给平台，产品代码里不再出现验证码、会话表、AppSecret。微信 AppSecret 也不再散落在各个产品里，只在平台加密保存一份。

这不是技术洁癖，是算账。一套登录、一套支付、一套后台，写一遍的成本是一遍，写五遍就是五遍，以后每个新产品还得再背一遍。把「证明你是谁」「钱有没有到账」「谁有权限」这些通用的东西抽到平台，产品才能真正只做自己的业务；想通这一点，后面合并账号、统一注销这些事，也都有了同一个落点。
