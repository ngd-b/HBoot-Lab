# HBoot-Lab #011｜微信里收到一堆发票，怎样整理成一份报销材料

出差或采购结束以后，发票经常散落在不同地方。

有些是自己拍的照片，有些保存在相册里，还有一些是同事、酒店或商家从微信聊天发来的 PDF。真正开始报销时，才发现一个文件里可能有好几张票，也可能一张发票带着多页明细。

如果只是把所有文件转发给财务，后面通常还要再补一遍整理：哪些属于这次报销，每张多少钱，原件在哪里，清单和文件能不能一一对应。

这篇文章不讨论复杂的财务系统，只解决一个具体问题：

**怎样把散落在微信和手机里的票据，整理成一份清楚、可检查、方便交付的报销材料。**

## 先弄清楚：最后要交的不是“一堆发票”

一份便于核对的报销材料，至少应该包含两部分：

1. 一份票据清单；
2. 与清单对应的原始文件。

清单里可以保留这些基本信息：

- 票据日期；
- 商家名称；
- 发票号码；
- 票据类型；
- 金额；
- 用途或分类；
- 必要的备注。

原始文件则保留照片或 PDF，不要只剩下一份手工填写的表格。

整理的目标不是把所有文件放进同一个文件夹，而是让清单里的每一条记录，都能找到对应原件；看到一份原件时，也能知道它属于哪次费用。

只要先确定这个结果，后面的步骤就会清楚很多。

## 第一步：把聊天文件和相册图片放进同一套流程

最容易遗漏的通常不是相册里的照片，而是微信聊天中的 PDF。

如果手工整理，可以先按一次报销任务建立文件夹，再分别检查相册、文件管理和相关聊天，把需要的原件集中到一起。不要边找到边改表格，否则很容易在不同入口之间来回切换，最后也不知道是否已经收齐。

使用《AI 发票助手》时，小程序首页可以直接选择三种来源：

- 拍照；
- 从相册选择；
- 从微信聊天选择 PDF。

聊天文件不需要先保存到相册，再重新寻找。选择以后，它会和照片进入同一套识别与整理流程。

<!-- 待补图：拍照、相册、微信聊天 PDF 三个入口 -->

无论使用哪种方式，都建议按“先归集、再检查、最后导出”的顺序处理。不要识别一张就立刻导出一张，那样只是把原来的零散文件换成了零散下载。

## 第二步：不要把 PDF 的每一页都当成一张发票

多页 PDF 是整理时最容易出错的地方。

一个五页文件，可能是五张不同的发票，也可能是一张发票加四页商品明细。如果简单地“一页生成一条记录”，明细页会被误认为新的票据；如果始终“一个文件生成一条记录”，多张发票又会被挤在一起。

判断时可以先看两个信息：

1. 页面上有没有明确标注发票号码；
2. 后续页面的发票号码有没有发生变化。

《AI 发票助手》目前采用偏保守的拆分方式：识别到明确标注、并且与前一张不同的发票号码时，才开始一条新记录；没有新号码的后续页面，默认继续归在前一张票据下面。

这样做是为了避免把发票明细或附件轻易拆开。

识别完成后，如果同一个 PDF 被拆成多张票据，页面会显示拆分数量，并在详情中保留每条记录对应的来源页码。这里仍然需要人工看一眼：拆分结果是否和原文件里的实际票据数量一致。

<!-- 待补图：多页 PDF 拆分数量，以及详情页中的来源页码 -->

记住一个简单原则：

**页数不等于票据数量，文件数也不等于票据数量。最终应该按真实票据来建立记录。**

## 第三步：识别完成后，重点检查这些字段

自动识别可以减少录入，但不应该跳过检查。

导出前，至少快速核对以下内容：

- 日期有没有识别错；
- 商家名称是否完整；
- 发票号码是否对应原件；
- 金额有没有小数点或位数错误；
- 票据类型和分类是否符合实际用途；
- 同一张票有没有被重复上传。

其中，日期、金额和发票号码最容易影响后续核对。分类可以批量调整，备注也可以之后补充，但原始字段如果有误，越晚发现越难回到对应文件确认。

如果识别失败，不要直接把失败记录混进最终清单。可以重新识别；确认文件本身不属于本次报销时，就从这次整理范围中移除。

这一步的目标不是让所有字段看起来都很整齐，而是保证清单能够忠实对应原件。

## 第四步：先筛选范围，再做批量整理

票据多起来以后，逐张打开修改会很慢。

可以先按日期、金额、票据类型、分类和处理状态缩小范围。例如：

- 只看这次出差日期内的票据；
- 找出所有交通和住宿费用；
- 检查仍然识别失败的记录；
- 单独查看金额较大的票据；
- 排除重复或不属于本次报销的文件。

确认范围以后，再批量修改分类、重新识别或删除不需要的记录。

《AI 发票助手》的 Web 端支持按这些条件筛选，也可以跨页选择多条票据。这样整理几十张票时，不需要每翻一页就重新选择一次。

<!-- 待补图：日期、金额、票据类型和分类筛选，以及跨页批量选择 -->

如果手工使用表格，也可以采用同样的方法：先录入全部记录，再用筛选器集中处理同一类问题，而不是按文件顺序一张张来回切换。

## 第五步：把清单和原件一起导出

整理完成后，不要只导出一份 Excel 就结束。

表格方便汇总和核对，但需要查看票面信息时，仍然要回到原始图片或 PDF。如果清单和原件分开存放、文件名又无法对应，接收材料的人仍然要重新寻找。

根据后续用途，可以选择：

- Excel：适合继续编辑、统计和提交；
- CSV：适合导入其他系统或做简单数据处理；
- 原件压缩包：把票据清单和对应图片、PDF 一起保存。

《AI 发票助手》可以按手工勾选的记录导出，也可以直接导出当前筛选范围。原件压缩包中会同时包含一份清单和原始文件；导出任务完成后会保留在历史中，不必一直停留在页面等待。

<!-- 待补图：Excel、CSV、原件压缩包和导出历史 -->

交付前再做最后一次数量核对：

- 清单共有多少条；
- 原件对应多少张真实票据；
- 多页 PDF 拆分后有没有重复计算同一个原文件；
- 是否还有识别失败或缺少金额的记录。

数量一致，不代表内容一定正确；但数量对不上，通常说明整理过程中还有遗漏或重复。

## 三个容易踩的坑

最后，把整个流程压缩成三个提醒。

### 1. 不要按文件数统计票据数

一个 PDF 可能包含多张票，一张票也可能占据多页。应该以真实票据记录为准，而不是以文件或页面为准。

### 2. 不要完全相信自动识别

识别的作用是减少录入，不是替你承担最终核对。日期、号码和金额至少要和原件快速比对一次。

### 3. 不要让清单和原件失去对应关系

只保留表格，后续无法查看原件；只保留原件，后续又很难汇总。最省事的交付方式，是让清单和原件一起保存。

## 一份可以直接照着做的检查清单

下次整理报销材料，可以按这个顺序完成：

- [ ] 检查相册、文件管理和相关微信聊天；
- [ ] 把本次报销涉及的图片与 PDF 统一归集；
- [ ] 确认多页 PDF 中真实包含几张票据；
- [ ] 核对日期、商家、号码、金额和类型；
- [ ] 排除重复、失败和不属于本次报销的记录；
- [ ] 按日期、用途或分类完成批量整理；
- [ ] 导出票据清单；
- [ ] 同时保存对应的图片和 PDF 原件；
- [ ] 最后核对清单条数与真实票据数量。

工具可以替你完成归集、识别、筛选和导出，但最终目标始终是同一个：

**让每一笔费用说得清，让清单里的每一条都找得到原件。**
